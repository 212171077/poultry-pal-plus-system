Prompt 1: Full Monorepo Analysis
======================================================

Analyze the entire Poultry Pal Plus monorepo (poultry-pal-service Spring Boot backend + poultry_pal_plus_app Flutter mobile app).
Perform a comprehensive code review covering:

**Backend (Spring Boot):**
1. Architecture: Does it follow Controller → Service → Repository → Domain correctly?
2. Are DTOs properly separated from entities? Are entities ever leaked in API responses?
3. Exception handling: Is there centralized exception handling or are exceptions handled ad hoc?
4. Security: Review @PreAuthorize annotations for consistency, check if sensitive data is ever exposed
5. Performance: Identify N+1 query risks, missing pagination, unoptimized queries
6. Code smells: Typos (e.g., "excption" package), TODO items left unresolved, dead code
7. Missing validation (@Valid usage, input sanitization)
8. Test coverage gaps (check which controllers/services lack tests)
9. API response consistency: Does every endpoint return { success, message, data }?
10. Hardcoded values, missing environment-based configuration

**Frontend (Flutter):**
1. Architecture: Is business logic leaking into UI widgets? (Check screens/ files)
2. State management: Is there a proper state management solution or is setState used everywhere?
3. Service layer: Is there only one monolithic service file? Should it be split?
4. Null safety: Are nulls handled safely throughout?
5. Widget size: Are any widgets too large? (e.g., coop_list_item.dart is 4225 lines)
6. Hardcoded API URLs in the service file
7. Error handling consistency across all API calls
8. Missing separation of concerns (models, services, state, UI)
9. No dependency injection pattern
10. Missing offline/caching support despite targeting low-connectivity users

**Cross-cutting:**
1. API contract alignment between backend DTOs and Flutter models
2. Missing features mentioned in copilot-instructions.md but not implemented
3. Security: Credentials stored in SharedPreferences (password in plain text?)

For each issue found, provide:
- File and line reference
- Severity (Critical / High / Medium / Low)
- Recommended fix
- A Copilot prompt I can use to implement the fix
